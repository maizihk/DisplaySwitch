# Windows 端开发清单

> Windows 端开发遵守仓库根目录 `AGENTS.md` 的通用开始、结束、Git 协作和硬件安全规则。
> 本文件只记录 Windows 任务、验收条件和进度，不重复通用约束。

## 当前边界

- 正式 Windows 实现是 `Windows/DisplaySwitcher.Native/`，技术栈为原生 C++/WinUI 3。
- `Windows/DisplaySwitcher.Launcher/` 是绿色版入口启动器，正式构建仍需要它。
- `Windows/DisplaySwitcher.Windows/` 是旧 C# 迁移参照，不参与正式构建；不要在其中实现新功能。
- `PROTOCOL.md` 是 Mac/Windows 通信的唯一规范；当前正式运行时为 v2-only。未经双端同步设计，不得单方面改变消息结构或行为。
- macOS 与 Windows 均已完成动态多显示器模型；Windows 端当前仅剩设置页和高 DPI 交互的实机验证待确认。
- 不要重写现有托盘、WinUI 3、USB 监控、UDP、DDC 或登录启动实现，只做可验证的渐进式迁移。

## P0：公开源码前必须完成

### W-001 清除个人硬件默认值

- [x] 新安装不再预设任何具体 USB VID/PID、ControlMyMonitor 个人路径、显示器路径、型号或输入源编号。
- [x] 新安装保持“未配置且不会执行 USB/DDC 动作”的安全状态。
- [x] W-001 当时保留已保存配置；DS-007 的不兼容升级现改为先备份 v3 或更早文件，再生成安全关闭的 v4 配置。
- [x] UI 使用通用名称，不再写死“小米”“Dell”或固定的两台显示器。
- [x] 清理 `README.md`、`Windows/README.md` 中作为产品默认值出现的个人硬件配置；如保留示例，必须明确标记为示例并使用中性占位值。
- [x] 配对码、本机路径、IP、设备 ID 和用户目录不得写入源码、测试快照或日志。

验收：删除本机配置后启动，不会切屏或触发 USB；设置页明确提示用户完成配置。

### W-002 动态多显示器模型

- [x] 用显示器配置集合替代 `redmi*` / `dell*` 固定字段，支持 0、1、2、3 台及更多显示器。
- [x] 每台显示器至少保存稳定标识、用户名称、原生 DDC 标识、兼容后端设备路径和各协同配置对应的对端输入源。
- [x] 使用稳定标识匹配显示器，不能依赖枚举顺序或 `DISPLAY1` / `DISPLAY2` 永久不变。
- [ ] 设置页可以添加、删除、重排和重新选择显示器；布局适配高 DPI。（代码完成；高 DPI 与实机交互待确认）
- [x] 原生 DDC 和 ControlMyMonitor 后端都遍历同一份动态配置。
- [x] W-002 曾提供旧双显示器迁移；DS-007 后不再执行该迁移，而是保留旧文件备份并安全重建 v4。
- [x] 未配置输入源或找不到显示器时只报告问题，不猜测输入值、不误操作其他显示器。

验收：用虚拟/模拟配置覆盖 0、1、2、3 台显示器、枚举顺序变化和显示器替换场景。

### W-003 交接状态机可测试化

- [x] 从 `Controller` 中分离纯状态机；网络、USB、时钟、唤醒和 DDC 由 Controller 适配器输入或执行状态机动作，可在测试中替换。
- [x] 使用虚拟时钟测试 150 ms 防抖、150 ms 重发、最多 4 次、600 ms 兜底和 6 秒在线窗口。
- [x] 覆盖 USB 在等待时返回、请求与 USB 到达顺序互换、确认丢包、对端离线和 `committed` 收尾。
- [x] 覆盖重复、过期、乱序、错误 source/target、错误配对码和错误 version。
- [x] `status_probe` / `status_response` 使用相同 `eventID`，且状态探测绝不触发唤醒、USB 或 DDC。
- [x] 历史 v1 状态机曾消费 17 组消息和 16 组状态机向量；DS-007 后正式工程已删除该状态机和这些测试引用。

验收：测试不依赖局域网和真实硬件，可重复运行且结果稳定。

### W-004 Windows CI

- [x] 新增 GitHub Actions Windows 工作流，至少执行依赖恢复、x64 Release 构建和自动测试。
- [x] 验证 `Windows/build-windows.ps1` 生成完整 `Windows/dist/`。

### DS-004 第一阶段：本机协同模型与 UI（历史实现，配置格式已由 DS-007 取代）

- [x] 本机配置升级为 `schemaVersion = 3`，随机生成并持久保存 `localEndpointID`，显示器目录与协同配置分离。
- [x] 协同页支持添加、删除、重命名、排序和多个配置同时开启；删除已开启配置前要求确认，且至少保留一个配置。
- [x] 每个配置保存对端主机、端口、NFC 配对码、已确认 endpoint/协议能力、显示器输入映射和本机触发设备引用。
- [x] Windows v2 配置迁移为一个旧对端配置，`MacInput` 迁入对端映射，`localInput` 保持 `null`，原文件保留备份。
- [x] 迁移、解析，以及正常 v3 设置保存的编码、临时写入、完整回读或原子替换失败时保留原数据并持久进入安全状态；当前实例立即停止协同和硬件副作用，只有用户成功保存合法 v3 配置才解除。
- [x] 托盘菜单按已启用且本机完整的配置名称生成，不增加“切换到本机”，多配置不退化选择第一项。
- [x] “检测”仅执行本机字段、显示器引用和缓存后端可用性检查，不发送网络消息或调用硬件动作。
- [x] 临时配置自动测试覆盖 C-001 至 C-015、边界校验、迁移、安全重启和显示器失败隔离；继续通过 v1 17+16 公共向量。
- [x] USB 学习按稳定协同配置 ID 锁定目标，记录开始设备基线并在 30 秒内收集新增候选；多候选必须明确选择，取消、超时、配置删除和迟到代际均不改原绑定。
- [x] USB 学习及候选确认期间暂停 UDP、自动 USB 交接、DDC、唤醒和旧异步结果；纯模拟覆盖 C-021、C-022。
- [x] 常规页提供关于页面，只使用公开产品、版本、架构、协议和项目链接数据；不读取本机配置，纯自动覆盖 C-023 零副作用和隐私边界。
- [ ] WinUI 3 配置增删排序、删除确认、托盘动态名称、USB 学习/候选/关于页面及高 DPI 布局仍需实机交互验证。

验收：自动测试与 x64 Release 构建已通过；未执行真实 UDP、USB、蓝牙、DDC、唤醒或防火墙操作。DS-005 v2 网络运行时不在本阶段。

- [x] 定义统一的枚举、能力检测、VCP 读取/写入、错误、取消和后端可用性接口。
- [x] 原生 Dxva2 与 ControlMyMonitor 作为独立硬件 DDC/CI 后端实现，输入源切换继续使用既有 `0x60` 语义。
- [x] 每台显示器按稳定逻辑 ID 关联；DS-007 后由一个全局控制通道选择原生或 ControlMyMonitor 回退，并显示可用、不支持或暂时失败。
- [x] 亮度 `0x10`、对比度 `0x12`、音量 `0x62` 支持独立开关、显式读取和提交式滑块写入；联动所有显示器默认关闭。
- [x] 后端、显示器或单项失败相互隔离；全零遥测、估计缓存、异常最大值、安全状态、取消和迟到结果按 DS-004 语义处理。
- [x] 纯模拟后端覆盖 C-016 至 C-020、C-024、后端不可用/回退、稳定 ID 重排、显式联动部分失败和零调用安全门；继续通过 v1 17+16 公共向量。
- [ ] 全局通道、三项回读/提交、托盘滑杆、联动、取消、状态提示和高 DPI 布局仍需实机交互验证；真实 DDC 兼容性须另行授权测试。

- [ ] 导出前自动脱敏并允许用户预览。

### W-204 协议 v2/HMAC

- [x] 按当前生效的 `PROTOCOL.md`、已批准的 DS-005 提案与 `contracts/protocol-v2/` 实现 v2 HMAC、路由与状态机；DS-007 后正式运行时只接受整数 version 2。
- [x] 使用 Windows CNG 实现 PBKDF2-HMAC-SHA256、规范化认证输入、常量时间校验、nonce/时间窗和重放防护。
- [x] Windows 原生测试接入共享 v2 向量，覆盖 1 条 NFC、4 条认证、20 条消息和 20 条状态机向量；不再引用 `contracts/protocol-v1/`。
- [x] 协同配置“检测”只发送 v2 探测，只接受匹配待处理 `eventID` 的响应；首次或变化的对端身份均需用户确认并立即原子保存。
- [x] 检测过程阻断 USB、蓝牙、唤醒与 DDC；常规 v2 `status_response` 也必须匹配尚未过期的待处理探测后才能刷新在线状态。
- [x] 双方 `peerEndpointID` 均为空时，接收端按数据报来源 host/port、配对凭据和唯一配置匹配 `targetEndpointID = null` 的首次探测；歧义、认证失败或 endpoint 冲突均零回复、零硬件副作用。

### W-205 自动发现

- [ ] 在安全模型确定后再做 Bonjour/mDNS 发现。
- [ ] 自动发现只提供候选设备，不自动信任、不自动交换配对码、不触发硬件动作。

### DS-007 设置、DDC 与 v2-only 收敛

- [x] 正式 Windows 运行时删除 v1 解析、状态机、发送、心跳和探测回退；version 1、缺失、类型错误和未知版本零回复、零在线刷新、零硬件副作用。
- [x] 本机配置升级为 schema v4；v3 或更早配置先保留递增后缀备份，再创建协同、USB 和 DDC 写入均关闭的安全默认值，不迁移旧字段。
- [x] 设置页统一为“常规 / USB 切换 / 协同 / 显示器 / 关于”，删除全局保存/取消并实现成功后更新运行时的即时原子保存、非法文本回滚和删除确认。
- [x] USB 页按当前配置选择或学习设备；协同页按自定义名称选择、增删排序和检测，不显示原始设备、本机身份或协议内部字段。
- [x] 独立关于页只读取公开元数据并保持零配置、网络和硬件副作用。
- [x] 显示器页使用全局控制通道与联动开关；每台显示器只显示读取按钮和亮度/对比度/音量的功能开关、托盘开关、滑杆和值。
- [x] 托盘只投影同时启用且允许托盘显示的项目，并提供真实滑杆；连续写入按显示器和项目 latest-wins 合并、串行执行，原生失败仅重试一次。
- [x] 模拟测试覆盖 Windows 适用的 DS-007 保存、v4、安全门、版本拒绝、关于、托盘、DDC 零值/隔离/联动/取消场景及全部 v2 公共向量。
- [ ] 五页紧凑布局、窄窗口/高 DPI、键盘焦点与辅助功能、托盘滑杆，以及真实 DDC/USB/v2 跨设备行为仍需实机验证。

## 当前不要做

- 不要修改或回退 macOS 源码来迁就 Windows 的旧模型。
- 不要从 C++/WinUI 3 改回 C#，也不要新建第三套 Windows 实现。
- 不要恢复协议 v1 运行时或添加只有单端认识的协议字段或消息。
- 不要为“提速”删除 150 ms 防抖、消息校验、重放保护或超时兜底。
- 未经用户明确确认，不要执行真实显示器输入源切换、真实 USB 交接、睡眠/唤醒测试或系统防火墙修改。
- 不要提交 `bin/`、`obj/`、`dist/`、个人证书、签名密钥、配对码、本机配置或诊断日志。
