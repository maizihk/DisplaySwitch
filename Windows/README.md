# Windows 托盘版安装、配置与测试

> 开发前请先阅读仓库根目录的 [`AGENTS.md`](../AGENTS.md)、
> [`PROTOCOL.md`](../PROTOCOL.md) 和
> [`DEVELOPMENT_CHECKLIST.md`](DEVELOPMENT_CHECKLIST.md)。

正式 Windows 实现位于 `Windows/DisplaySwitcher.Native/`，使用原生 C++/WinUI 3；
`Windows/DisplaySwitcher.Launcher/` 是绿色版入口。`Windows/DisplaySwitcher.Windows/`
只是旧 C# 迁移参照，不参与正式构建，也不承载新功能。

## 支持环境与绿色版

- 目标平台为 x64，最低 Windows 10 版本 1809（build 17763），也支持 Windows 11。
- 当前是 framework-dependent 绿色版，需要预装 Microsoft Windows App Runtime 2.4 x64。
- 程序不依赖 .NET，Release 使用静态 C/C++ 运行库。
- 当前产物是未签名测试构建，不等同于正式代码签名版本。

安装时复制完整 `Windows\dist\` 目录到固定位置，保留 `runtime` 子目录，然后运行
`DisplaySwitch.exe`。程序会常驻托盘；全新配置默认关闭协同、USB 自动切换、全部 DDC
写入和详细诊断记录，不会猜测设备、显示器、输入源、地址或配对码。

## schema v5 本机配置

Windows 当前只读取 `schemaVersion = 5`。配置保存在当前用户的应用数据目录，不放在绿色版
目录，也不通过协同消息同步。首次启动会生成随机并持久保存的本机逻辑身份；该值不从用户、
设备或硬件信息派生。

schema v4 配置会先完整复制为本机 `.pre-v5.backup`（同名备份存在时使用递增后缀），再原子
迁移到 v5。迁移保留常规设置、显示器目录、DDC 设置和协同配置，但不会从旧协同配置猜测 USB
设备、输入映射或联动目标；新 USB 功能默认关闭。更早或未知版本安全拒绝。解析、临时写入、
完整回读或原子替换失败时，旧配置保持
不变并写入持久安全标记，当前进程和重启后的进程都会阻断 UDP、USB、DDC、唤醒和输入源
切换，直到用户成功保存合法 v5 配置。

v5 将本机显示器目录、独立 USB 切换配置与协同配置分开：

- 显示器按稳定逻辑 ID 保存内部硬件关联、三项功能开关、三项托盘开关及可信估计缓存。
- 协同配置保存自定义名称、对端地址和端口、NFC 配对码、已确认的对端身份及每显示器输入映射。
- USB 切换配置只在本机保存一个选定设备、每显示器目标输入源、联动开关和一个明确的联动目标。
- 控制通道是全局设置，不再允许每台显示器独立选择后端。
- 新显示器的亮度、对比度、音量功能开关及对应托盘开关全部默认关闭。

USB 和协同的显示器输入源允许留空：空白/`null` 表示该显示器不参与切换，`1...65535`
是有效值，`0`、负数、非数字和溢出值会被拒绝。旧 v5 配置中的 `0` 会原子迁移为空映射；
迁移失败保留原文件并进入安全状态。部分显示器留空时只报告 `missing_mapping`，其他有效映射
继续独立执行；全部为空时不能启用或执行。原生输入源传输在调用 DXVA2 前还会再次拒绝 `0`。

## 设置界面

设置窗口依次包含“常规”“USB 切换”“协同”“显示器”“诊断”“关于”六页，没有全局保存或取消
按钮：

- 开关、选择器及配置增删排序在原子保存成功后立即更新运行时。
- 文本字段在结束编辑或按 Return 时校验；非法值恢复最后有效内容并显示就地错误。
- 不完整协同配置不能开启。删除配置始终要求确认，且至少保留一个配置。
- 对端身份首次发现或变化时必须由用户确认；确认后立即保存，不再等待额外保存操作。
- 普通页面不显示原始 USB 标识、设备路径、本机身份字段名或协议内部字段。

“USB 切换”页独立选择或学习一个本机设备，为每台显示器填写“USB 离开后切到的输入源”，
并提供默认关闭的“USB 自动切换”和“联动协同”。首次状态只建立基线；接入变离开时立即异步
执行本机 DDC，不等待网络；离开变接入时只唤醒本机。联动开启后可选择一个完整协同配置，
与 DDC 同时发送一次认证 `wake_display`，发送失败不会阻断或回滚 DDC。USB 学习在 30 秒内
收集全新设备，以及学习开始时已连接、随后离开并重新接入的候选；多个候选必须由用户选择，取消、超时或迟到回调均保留原绑定。学习和确认期间
暂停网络与全部硬件副作用。

USB 配置由用户修改且成功持久化后，页面固定底部短暂显示绿色“✓ 已保存”。该状态与协同页
保存反馈相互隔离；切换页面、切换正在编辑的协同配置或重新加载只清除短暂成功提示，不清除
持久化失败提示。设备学习、网络检测、DDC 和其他非保存操作不会产生“已保存”。

“协同”页按用户自定义名称选择配置，可添加、删除、重命名和排序，并编辑地址、端口、配对
码和每显示器输入源映射。检测只发送 v2 `status_probe`，只接受匹配当前待处理 `eventID`
的响应；检测不调用 USB、唤醒、DDC 或输入源切换。

“关于”页只读取公开应用元数据，显示图标、产品名、版本/构建、平台/架构、协议 v2、项目、
MIT 许可证和 Windows 第三方说明。它不读取本机配置或硬件标识，打开页面不会触发网络或
硬件操作。

“常规”页的“详细诊断记录”默认关闭；旧 v5 配置未包含该字段时也按关闭处理。关闭时不会创建
或保留详细事件，诊断页仍显示配置、能力和基本成功/失败摘要。开启后只收集开启之后产生的本次
会话脱敏轨迹；开关任意方向切换都会清空内存和磁盘中的旧轨迹。

“诊断”页提供只读且可选择的脱敏预览，并仅允许复制当前可见文本。预览从配置快照和现有
内存状态生成，不会发送探测、建立连接、枚举或访问 DDC、执行 USB 交接、唤醒或切换输入源。
协同配置、显示器、会话和操作分别使用本次会话内的 `P1`、`D1`、`S1`、`O1` 匿名编号；
配对密码、地址、endpoint、认证字段、事件/nonce、用户路径、显示器/USB 原始标识和用户自定义
名称不会出现在预览中，匿名映射也不会保存或同步。诊断日志入口使用安全事件及数值字段白名单，
未知字段会在记录前删除。显示器页面只展示读取/写入成功或失败等简明结果，不展示 HANDLE、
传输类型、错误码、重试次数或校验信息。

## v2-only 协同

正式运行时只允许顶层整数 `version = 2` 的 UDP 数据报进入 v2 解析器。version 1、缺失版本、
错误类型和未知版本均直接拒绝，不回复、不刷新在线状态，也不触发 USB、唤醒、DDC 或输入源
切换。Windows 正式工程中不再包含 v1 解析器、状态机、发送、心跳或检测回退路径。

v2 使用 NFC 配对码经 PBKDF2-HMAC-SHA256 派生方向密钥，并校验规范化认证输入、常量时间
标签、10 秒时间窗、随机 nonce、20 秒重放缓存和 endpoint 路由。手动选择只定向指定配置，
保留 150 ms 重发和 600 ms 本机兜底。USB 不进入协同状态机；合法 `wake_display` 只请求一次
本机显示器唤醒，不回复、不写 DDC，并与本机 USB 接入唤醒共用 2 秒合并器。

配对码在 NFC 规范化后必须为 8 至 128 个 UTF-8 字节。配对码、USB/显示器标识和本机路径
不会进入 v2 数据报，也不得写入日志、Issue 或 Git。

## 显示器与 DDC 控制

“显示器”页顶部只有联动调节开关和重新检测入口。页面只展示当前 Windows
逻辑显示目标，不把同一 target 下的多个底层 `PHYSICAL_MONITOR` 句柄当成多台显示器。每项优先使用保存的用户名称或 Windows 系统友好名称；同名项只用仅本机可见的序号区分显示，该名称和顺序不作为物理身份。页面仅提供“读取 DDC 参数”以及亮度、对比度、音量三行紧凑控制；每行包含功能开关、
托盘开关、滑杆和值。

支持的普通硬件 DDC 项为亮度 `0x10`、对比度 `0x12` 和音量 `0x62`。普通界面不显示这些编号、
底层 API 名称、设备路径或可编辑显示器名称。关闭某项功能后，该项零读取、零写入，滑杆和
托盘开关同时禁用。“读取 DDC 参数”只读这三项，不写输入源、不唤醒显示器、不触发协同。

输入源切换使用独立的原生传输接口和切换服务，不通过普通 `IDdcBackend`，也不会进入亮度、
对比度或音量缓存。两条接口仍共享同一个 DXVA2 物理显示器会话、唯一绑定、句柄生命周期、
拓扑 generation 与串行锁，因此不会复制枚举逻辑或按名称/顺序重新选择目标。USB 离开和协同
切屏都只调用输入源传输；普通 DDC 失败与输入源失败相互隔离。

正式 Windows 实现只包含 Windows 原生 Dxva2 DDC/CI 后端。原生枚举、读取或写入失败会明确
显示失败，不会启动外部显示器工具、选择其他后端或伪装成功。旧本机配置中多余的后端选择、
外部工具路径和兼容显示器路径会被安全忽略，并且不会在后续保存时再次写入。

- 默认只调节当前显示器；“联动调节所有显示器”必须由用户显式开启。
- 联动只作用于同时启用同一 DDC 项的显示器，单台失败不会阻止或污染其他显示器。
- 报告最大值异常时，界面范围使用 `max(100, current)`。
- 单项零值合法；同一显示器三项均成功返回零时视为不可信，不覆盖缓存。
- 读取失败可显示按稳定 ID 和项目保存的估计值；只有可信读取或成功写入才更新缓存。
- 当前拓扑由 `QueryDisplayConfig` / `DisplayConfigGetDeviceInfo` 提供 adapter LUID、target ID 和接口路径，再与 SetupAPI 的 Container ID / EDID 强身份匹配。这些硬件信息仅保存在本机，不写日志或通过协同同步。
- 持久物理显示器目录与当前会话拓扑分离。只有本地控制台得到完整、非空且可信的物理快照时才协调并保存目录；远程桌面会话、远程/镜像显示目标、访问受限、失败、部分或空枚举都只保留现有目录与映射。
- 远程桌面会话中不创建虚拟显示器条目，也不执行 DDC 读取、写入或输入源切换。设置页会提示已保留本地物理显示器配置；返回本地控制台后由显示变化或会话通知使拓扑失效，再按强身份重新解析。
- 每个逻辑显示器在操作前必须唯一解析为一个当前物理 DDC 句柄。同型号无序列号、重复身份、多句柄或旧配置多候选会明确显示歧义/需重新确认，不会依次试写、选第一项或执行任何 DDC。
- 拓扑 generation 在热插拔、`WM_DISPLAYCHANGE`、接口变化、枚举差异或句柄失效时递增并释放旧句柄。读写中 generation 改变时，即使底层返回成功也丢弃结果并停止剩余批量操作。明确句柄失效只允许一次刷新重试，不使用固定延迟或无限重试。
- 显示器暂时断开或休眠时标记离线，保留用户名称、DDC 开关、托盘开关、输入源、USB 映射和协同映射，不根据短暂的枚举结果自动删除。

托盘只为 `enabled = true && showInTray = true` 的项目创建实际滑杆，配置变化后立即刷新。
连续变化按“显示器 + DDC 项”进行 latest-wins 合并；同一工作器串行提交，配置变化、取消或
安全闸门关闭会丢弃待写值，迟到结果不会更新缓存或界面。

显示器、GPU 驱动、线材、转接器、扩展坞或 KVM 可能不支持或不透传 DDC/CI，不同控制项也
可能分别成功或失败。自动测试只能证明软件的隔离与安全语义，不能替代真实硬件兼容性验证。

## 构建与自动测试

构建机需要 Visual Studio 的 C++ 桌面开发和 Windows App SDK C++ 组件。在 PowerShell 中运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Windows\build-windows.ps1
```

脚本执行 x64 Release 构建和无硬件原生测试，生成：

```text
Windows\dist\DisplaySwitch.exe
Windows\dist\runtime\...
```

脚本检查入口、runtime 必需文件以及完整绿色版小于 20 MiB。自动测试使用临时配置、模拟时间、
模拟网络、模拟 USB 和模拟 DDC，另覆盖显示器重复句柄、枚举重排/断开/重接、友好名称、原生失败零回退、句柄释放和 USB 离开后重接学习。测试读取 `contracts/protocol-v2/` 的 1 条 NFC、4 条认证、20 条
消息和当前 6 条状态机向量，并读取 `contracts/usb-switch-v1/` 的 USB-001 至 USB-016；不再读取
`contracts/protocol-v1/`。测试不会访问真实局域网、USB、
DDC、显示器唤醒、输入源、防火墙或系统设置。

## 实机验证边界

未经明确授权，不应为验证而执行真实 DDC 写入、输入源切换、USB 交接、唤醒或防火墙修改。
建议先验证六页布局、即时保存/回滚、配置名称、托盘动态增删、键盘焦点和高 DPI；随后只读
DDC 参数。获得授权并准备手动恢复显示器输入源后，再分别验证三项 DDC 写入、协同和 USB
自动交接。
