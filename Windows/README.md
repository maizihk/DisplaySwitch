# Windows 托盘版安装、配置与测试

> **开发前必读：** Windows 端 Codex 或开发者开始修改前，请先阅读仓库根目录的
> [`AGENTS.md`](../AGENTS.md)、[`PROTOCOL.md`](../PROTOCOL.md) 和
> [`DEVELOPMENT_CHECKLIST.md`](DEVELOPMENT_CHECKLIST.md)。项目约束定义通用流程与安全边界，清单记录 Windows 当前优先级和验收条件。

正式 Windows 实现位于 `Windows/DisplaySwitcher.Native/`，使用原生 C++/WinUI 3。`Windows/DisplaySwitcher.Windows/` 只是旧 C# 迁移参照，不参与正式构建；其中的旧字段仍用于理解和验证兼容迁移，不应删除或用于实现新功能。

## 支持环境与安装

- 工程最低目标为 Windows 10 版本 1809（build 17763），也支持 Windows 11；当前交互与真实硬件兼容性仍以待验项目为准。
- 绿色版是 x64、framework-dependent 构建，需要预先安装 Microsoft Windows App Runtime 2.4 x64。
- 程序不依赖 .NET，也不需要另装 Visual C++ Redistributable；Release 使用静态 C/C++ 运行库。
- 当前产物是未签名测试版本，不等同于商业代码签名的正式发行版。SmartScreen 出现未知发布者提示时，应先核对文件来源。

安装步骤：

1. 安装 Microsoft Windows App Runtime 2.4 x64；已经安装时跳过。
2. 复制完整的 `Windows\dist\` 目录到固定位置，保留 `runtime` 子目录及其中全部文件。
3. 运行根目录的 `DisplaySwitch.exe`。程序常驻 Windows 托盘，不会自动执行未配置的 USB 或 DDC 动作。
4. 从托盘菜单打开“设置…”。如需局域网协同且 Windows 防火墙询问是否放行，应只考虑可信的专用网络；不要为此关闭防火墙。

## schema v3 本机配置

Windows 当前使用本机 `schemaVersion = 3`。配置保存在当前用户的本地应用数据目录，不放在绿色版程序目录，也不随协同消息发送。新安装会生成随机、持久的本机 endpoint ID，但不会根据用户名、设备或硬件标识派生它。

schema v3 将两类数据分开：

- **显示器目录**：每台显示器只有一份记录，包含稳定逻辑 ID、自定义名称、每台后端选择、原生 DDC 标识、可选 ControlMyMonitor 字符串、三项功能开关和估计缓存。
- **协同配置**：每个配置包含自定义名称、对端 host、端口、配对码、对端 endpoint/协议能力、按显示器稳定 ID 保存的对端输入映射，以及本机触发设备引用。

协同配置名称是用户自定义标签，不根据名称推断目标是 Mac、Windows 或其他角色。设置页支持添加、删除、重命名、排序和同时开启多个配置。托盘只为已开启且本机字段完整的配置显示 `切换到 {配置名称}`，不提供“切换到本机”。

当前生效的网络运行时仍是 [`PROTOCOL.md`](../PROTOCOL.md) 定义的 UDP v1，协议角色仍为 macOS 与 Windows。为避免暗中选择错误目标，v1 兼容桥只在本机目录恰好有一个协同配置时工作；保存多个配置不会自动选择列表第一项。多目标网络协同、发现和 HMAC 属于后续 DS-005，不在当前 Windows 运行时中。

旧 Windows 配置会迁移到 schema v3：旧 `MacInput` 和固定显示器字段只作为兼容输入读取，转换为一个旧对端协同配置及按稳定显示器 ID 的映射；Windows `localInput` 保持未知，不会猜测。迁移、解析或原子写回失败时保留原文件并持久进入安全状态，阻断 UDP、USB 自动切换、DDC 和唤醒，直到用户成功保存合法配置。

## 配置显示器与协同

首次配置建议按以下顺序进行：

1. 在“显示器”页按实际数量添加显示器，填写中性、自定义名称。
2. 为每台显示器选择 `Windows 原生 Dxva2` 或 `ControlMyMonitor 回退`，再选择或填写与该后端对应的显示器标识。
3. 在“协同”页添加配置，填写自定义名称、对端 host、端口、配对码及每台显示器对应的对端输入源。
4. 配对码会在 NFC 规范化后按 UTF-8 计算，必须为 8 至 128 字节。它不是加密或强身份认证，只适合可信局域网；不得写进 Issue、日志或 Git。
5. 如需 USB 自动切换，在“USB 切换”页读取当前设备并明确选择触发设备。程序不会预选 USB VID/PID。
6. 使用协同配置中的本机检测检查字段、显示器引用及已缓存的后端可用性。检测不会发送网络消息，也不会读取或写入 DDC、切换 USB 或唤醒显示器。
7. 全部字段核对后，再由用户主动开启所需协同配置、USB 自动切换或登录启动。

配置中的 host 可以是可信局域网内的 IP 或主机名，端口默认 `49731`。显示器输入源编号由显示器与接口决定，必须由用户核对；项目不会提供个人设备默认值。

## W-201 硬件 DDC 控制

每台显示器可以独立选择后端：

- **Windows 原生 Dxva2**：直接调用 Windows 物理显示器 DDC/CI API，不依赖外部工具。
- **ControlMyMonitor 回退**：调用用户自行提供的 ControlMyMonitor 执行硬件 DDC/CI，适合原生后端在特定显示器、驱动或链路上不可用的情况；它不是软件调光功能。

输入源切换继续使用 VCP `0x60`。W-201 还提供：

| 控制 | VCP code | 行为 |
| --- | --- | --- |
| 亮度 | `0x10` | 每台显示器独立开关、显式读取、点击“应用”后写入 |
| 对比度 | `0x12` | 每台显示器独立开关、显式读取、点击“应用”后写入 |
| 音量 | `0x62` | 每台显示器独立开关、显式读取、点击“应用”后写入 |

- 关闭某项功能后，该显示器对该 VCP code 零读取、零写入，滑块和提交按钮不可操作。
- 拖动滑块本身不会连续写 DDC；只有用户点击“应用”才提交一次。
- 默认只控制当前显示器。“联动所有显示器”必须由用户显式开启，且单台失败不会阻止或污染其他显示器。
- 显示器和缓存按稳定逻辑 ID 与 VCP code 关联，不依赖当前枚举顺序。
- 报告最大值小于 10 或小于当前值时，界面范围使用 `max(100, current)`。
- 单项返回零是合法值；同一显示器三项都成功返回零时视为不可信遥测，不会覆盖已有缓存。
- 读取失败时可以显示按稳定 ID 保存的估计缓存；只有可信读取或成功写入才更新缓存。
- 后端会明确报告可用、不支持或暂时失败。配置安全状态、取消和失效的异步结果不会提交缓存或继续发起动作。

这些语义已由纯模拟后端覆盖 C-016 至 C-020、C-024，以及失败隔离、回退、取消、显示器重排和安全状态。真实 Dxva2/ControlMyMonitor 的三项读数、最大值、零值、联动和取消交互尚未完成实机验证，不应根据模拟测试提前宣称兼容。

## DDC/CI 限制与回退

显示器必须支持并启用 DDC/CI。即使显示器本身支持，GPU 驱动、线材、转接器、扩展坞、KVM 或其他链路也可能不透传 DDC/CI；不同 VCP code 还可能分别支持或失败。

原生后端失败不表示软件可以安全地用屏幕叠层模拟硬件亮度。可以在设置中为该显示器明确改用 ControlMyMonitor 回退，但仍应先核对其可执行文件和显示器字符串。程序不预设 ControlMyMonitor 路径、显示器路径、输入源或任何个人硬件信息。

重新排序显示器不会改变稳定身份。暂时断开的显示器保留原配置，重新接入后按稳定标识匹配；找不到显示器时只报告问题，不会把配置绑定到枚举中的另一台显示器。

## 首次测试的安全边界

首次实机测试应保持参与电脑均处于运行状态，并确保能够手动恢复显示器输入源。不要从整机睡眠、无人值守或只能远程访问的环境开始。

建议分开验证：

1. 先只检查托盘、设置保存/加载、配置名称和状态提示。
2. 再检查显式 DDC 读取及不支持/暂时失败提示。
3. 获得明确授权并确认恢复方法后，才测试亮度、对比度、音量或输入源写入。
4. 最后再单独验证 USB 自动交接、协同等待和显示器唤醒。

托盘中的 `切换到 {配置名称}`、三项“应用”按钮和自动交接都可能写入真实 DDC。开发自动测试不会代替这些实机验证。

## 构建与自动测试

构建机需要 Visual Studio，并安装“使用 C++ 的桌面开发”和 Windows App SDK C++ 组件。在 PowerShell 中执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Windows\build-windows.ps1
```

脚本执行 x64 Release 构建和无硬件自动测试，生成：

```text
Windows\dist\DisplaySwitch.exe
Windows\dist\runtime\...
```

构建会验证入口、`runtime/` 必需文件和整个绿色版目录小于 20 MiB。复制或分发时必须保留完整 `Windows\dist\`，不能只复制入口 EXE。

自动测试使用临时配置、模拟时间和模拟后端，覆盖 schema v3 迁移/安全状态、动态多显示器、W-201 DDC 语义，以及协议 v1 的 17 条消息向量和 16 条状态机向量。测试不会访问真实 UDP、USB、Bluetooth、DDC、显示器唤醒或防火墙。

## 隐私与诊断

本机配置可能包含显示器稳定标识、USB VID/PID、对端 host、配对码和 ControlMyMonitor 路径。这些值只能保存在本机，不应复制到公共测试、日志、Issue 或 Git 提交。分享诊断信息前必须预览并脱敏；当前诊断导出/预览功能仍属于未完成清单项。
