# DS-022：输入源空值与零值安全约束

状态：提案，待双端协调批准。

## 问题

现有 `contracts/usb-switch-v1/usb-switch-vectors.schema.json` 允许输入源值 `0`。Windows 原生实现最终使用 MCCS 输入源 VCP `0x60`，将 `0` 传给显示器没有可移植语义，可能导致显示器异常。空白映射与数值零必须在数据模型中明确区分，不能依赖界面隐藏。

## 提议语义

- `null` 或缺少映射：该显示器不参与本次输入源切换。
- 整数 `1...65535`：有效输入源值。
- `0`、负数、非整数和大于 `65535`：无效值，禁止保存为有效映射并禁止硬件写入。
- 某显示器缺少映射时产生既有 `missing_mapping` 结果；同一批次内其他有效显示器继续独立执行。
- 协同配置至少需要一台当前显示器具有有效映射才能启用；不再要求每台显示器都有映射。

本提案不改变网络消息、认证、重放保护、时序或跨端硬件标识。

## 兼容与迁移

1. 读取旧配置时，把输入源 `0` 原子迁移为 `null`/缺少映射。
2. 若迁移后没有任何有效映射，相关 USB 自动切换或协同配置保持关闭。
3. 迁移写入继续使用临时文件、回读校验和原子替换。
4. 迁移失败时保留原始文件，写入持久安全标记，并阻断网络与硬件副作用，直到用户成功保存合法配置。
5. 待双端批准后，将 `contracts/usb-switch-v1/usb-switch-vectors.schema.json` 中映射及动作的 `minimum` 从 `0` 调整为 `1`；`null` 和 `missing_mapping` 语义保持不变。

Windows 可先实施更严格的本机安全边界；macOS 适配和共享契约修改应由各自任务完成。本提案不授权修改 `PROTOCOL.md` 或 macOS 实现。

## 双端测试样例

| 场景 | 配置输入 | 预期结果 | 硬件写入 |
| --- | --- | --- | --- |
| 空映射 | `null` | `missing_mapping` | 0 |
| 最小有效值 | `1` | 切换该显示器 | 1 次，值为 1 |
| 最大有效值 | `65535` | 切换该显示器 | 1 次，值为 65535 |
| 旧零值 | `0` | 迁移为 `null`，必要时关闭功能 | 0 |
| 部分映射 | D1=`null`，D2=`17` | D1 `missing_mapping`，D2 继续 | 仅 D2 一次 |
| 全部为空 | 全部 `null` | 不允许启用或执行 | 0 |
| 迁移写入失败 | 旧配置含 `0` | 原文件保留并进入安全状态 | 0 |
