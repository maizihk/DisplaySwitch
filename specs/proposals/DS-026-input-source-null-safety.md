# DS-026：输入源空值与零值安全约束

状态：已批准（2026-09-02）。

## 问题

批准前，`contracts/usb-switch-v1/usb-switch-vectors.schema.json` 允许输入源值 `0`。Windows 原生实现最终使用 MCCS 输入源 VCP `0x60`，将 `0` 传给显示器没有可移植语义，可能导致显示器异常。空白映射与数值零必须在数据模型中明确区分，不能依赖界面隐藏。

## 批准语义

- `null` 或缺少映射：该显示器不参与本次输入源切换。
- 整数 `1...65535`：有效输入源值。
- `0`、负数、非整数和大于 `65535`：无效值，禁止保存为有效映射并禁止硬件写入。
- 某显示器缺少映射时，Mac 与 Windows 均产生既有 `missing_mapping` 结果；同一批次内其他有效显示器继续独立执行。
- USB 自动切换和协同配置都至少需要一台当前显示器具有有效映射才能启用；不要求每台显示器都有映射。

本提案不改变网络消息、认证、重放保护、时序或跨端硬件标识。

## 兼容与迁移

1. 双端读取旧配置时，把输入源 `0` 原子迁移为 `null`/缺少映射。
2. 若迁移后没有任何有效映射，相关 USB 自动切换或协同配置保持关闭。
3. 迁移写入继续使用临时文件、回读校验和原子替换。
4. 迁移失败时保留原始文件，写入持久安全标记，并阻断网络与硬件副作用，直到用户成功保存合法配置。
5. `contracts/usb-switch-v1/usb-switch-vectors.schema.json` 中映射及 `switchDisplay` 动作的输入源范围统一为 `1...65535`；映射继续允许 `null`，既有 `missing_mapping` 原因保持不变，不新增 `invalid_mapping`。
6. 双端最终硬件写入口仍需独立拒绝无效值，不能只依赖界面、配置解析或公共向量。

Windows 已先完成本机多层安全边界；Mac 与 Windows 必须共同遵守本提案批准后的公共合同。本提案不授权修改 `PROTOCOL.md`，本次共享合同更新也不修改 macOS 源码。

| 场景 | 配置输入 | 预期结果 | 硬件写入 |
| --- | --- | --- | --- |
| 空映射 | `null` | `missing_mapping` | 0 |
| 最小有效值 | `1` | 切换该显示器 | 1 次，值为 1 |
| 最大有效值 | `65535` | 切换该显示器 | 1 次，值为 65535 |
| 旧零值 | `0` | 迁移为 `null`，必要时关闭功能 | 0 |
| 部分映射 | D1=`null`，D2=`17` | D1 `missing_mapping`，D2 继续 | 仅 D2 一次 |
| 全部为空 | 全部 `null` | 不允许启用或执行 | 0 |
| 迁移写入失败 | 旧配置含 `0` | 原文件保留并进入安全状态 | 0 |
