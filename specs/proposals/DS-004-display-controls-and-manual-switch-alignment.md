# DS-004：显示器目录与多协同配置提案

## 状态

- 状态：DRAFT（等待用户批准详细本机数据和 UI 行为）
- 功能编号：DS-004
- 任务类型：cross-platform
- 基线：`24a4ed7bbfab0eb9726ed6261afe5ad56e3f4df7`
- 当前网络协议：保持 `version = 1`
- 公共 contracts：保持 `schemaVersion = 1`
- 两端本机配置：建议升级为 `schemaVersion = 3`
- 关联协调记录：`coordination/DS-004.md`
- 后续协议提案：DS-005 多目标协同协议 v2

用户已决定 Windows 补齐亮度、对比度、音量和回读控制；每个平台不再提供“切换到本机”，而是按协同配置显示可自定义名称的对端入口；对端信息改为可添加的多个协同配置；Windows 补齐 USB 学习和关于页面。

本提案只定义本机配置、显示器控制和 UI。手动协同唤醒、多配置自动目标发现、USB/蓝牙到达消息以及同系统设备角色由 DS-005 定义。未经 DS-005 批准，平台不得把这些新语义塞入现有 v1 消息。

## 当前行为

### macOS

- 菜单同时有“切换到 Mac”和“切换到 Windows”，名称固定。
- 每台显示器有名称、selector、Mac/Windows 输入源、DDC 读取开关以及亮度、对比度、音量控制。
- 支持 USB 学习和关于页面。
- 一台 Dell 显示器此前通过 `m1ddc` 出现三项均返回零的不可信读数；切换到原生接口后的准确性尚未实机验证。

### Windows

- 托盘只有硬编码的“手动切换到 Mac”。
- 每台显示器保存名称、稳定标识/兼容路径和 Mac 输入源。
- 只有输入源写入，没有产品化的亮度、对比度、音量、回读和联动控制。
- USB 只能刷新并选择当前设备，没有学习流程；设置窗口没有关于页面。

两端目前都只有一组对端 IP/主机名、端口、配对码和显示器输入映射，无法保存多个目标配置。

## 公共用户模型

### 1. 显示器目录

显示器是本机全局资源，只维护一份。每台显示器至少包含稳定逻辑 ID、用户名称、平台原生 DDC 识别信息、可选兼容后端信息、本机输入源 `localInput`、DDC 读取总开关，以及亮度/对比度/音量独立功能开关和调节入口。

硬件识别信息不得复制到每个协同配置。协同配置只通过稳定逻辑 ID 引用显示器，并保存该对端对应的输入源。

### 2. 协同配置

原“对端”或“双端协同”页面统一更名为“协同”。用户可以添加多个配置，例如“工作电脑”“游戏主机”“备用电脑”。每个配置包含自定义名称、对端 IP/主机名、对端端口、配对码、协同开启状态、每台显示器的对端输入源、本机学习到的 USB/蓝牙触发绑定和“检测”按钮。

多个配置可以同时开启。手动定向协同、单配置自动协同和多配置目标发现由 DS-005 状态机处理。

### 3. 首次启动和配置管理

- 全新安装创建一个空的“配置 1”，使用随机 UUID，协同关闭。
- 主机名、配对码、显示器输入和触发设备均为空；端口默认 `49731`。
- 用户可以添加、重命名、排序和删除配置，但界面至少保留一个配置。
- 删除已开启配置前必须确认；删除后取消该配置的未完成本机操作。网络事件清理由 DS-005 定义。
- 配置名称在本机范围内忽略大小写后必须唯一。

### 4. 菜单与手动入口

- macOS 移除“切换到本机”；Windows 不新增“切换到本机”。
- 菜单按完整且已开启的协同配置生成 `切换到 {配置名称}`。
- 菜单不得硬编码 Mac 或 Windows，也不得根据名称推断平台或输入源。
- 点击入口时只读取该配置按稳定显示器 ID 保存的对端输入源。
- 缺少映射的显示器不执行写入；其他显示器可以独立完成并报告部分失败。
- 协同唤醒、确认和降级由 DS-005 定义；DS-004 不允许用 v1 `handover_request` 冒充新的手动意图。

### 5. 检测按钮

每个配置都有“检测”按钮。DS-004 只定义本机行为：校验名称、主机、端口、配对码和显示器映射，显示引用显示器是否仍存在及本机 DDC 后端可用性。检测不写入 DDC、不切换输入源、不触发 USB/蓝牙交接、不唤醒显示器。网络检测、响应关联和版本兼容由 DS-005 定义。

即使协同尚未开启，也允许先检测完整配置。

### 6. 亮度、对比度和音量

| 控制 | VCP code | 用户值 |
| --- | --- | --- |
| 亮度 | `0x10` | `0...有效最大值` |
| 对比度 | `0x12` | `0...有效最大值` |
| 音量 | `0x62` | `0...有效最大值` |

共同语义：

1. 控件按稳定显示器 ID 关联，不依赖枚举顺序。
2. 每项功能可按显示器关闭；关闭后不读取、不显示可操作滑块，也不接受写入。
3. 用户可以单独控制显示器，或显式开启“联动所有显示器”；默认不暗中联动。
4. 滑块只在用户提交变更时写入，避免无界连续 DDC 操作。
5. 报告最大值小于 10 或小于当前值时，UI 范围使用 `max(100, current)`。
6. 同一显示器三项均成功返回零时视为不可信遥测；单项为零仍可合法。
7. 读取失败时可显示按稳定 ID 和 VCP code 保存的估计缓存；不得用失败结果覆盖缓存。
8. 写入成功后才更新缓存；单台或单项失败不得影响其他显示器。
9. 配置安全状态阻断所有读取、写入、缓存提交和异步迟到结果。

### 7. USB 与蓝牙学习

- macOS 保留 USB 学习；Windows 增加同等 USB 学习，而不仅是刷新当前设备列表。
- 学习开始时记录设备基线，窗口为 30 秒，只把期间新增或消失的设备列为候选，并由用户明确选择。
- 学习期间不得触发 DDC、网络、唤醒或自动交接。
- 取消、超时、窗口关闭或配置重载后保留原绑定并丢弃迟到结果。
- 蓝牙学习作为相同的本机触发设备抽象记录在配置中；实际连接状态、网络声明和权限行为由 DS-005 及平台任务进一步限定。
- 原始 USB/Bluetooth 标识、序列号和路径只能保存在本机。

### 8. 关于页面

Windows 增加与 macOS 对等的关于页面；macOS 核对现有页面。至少显示产品名、从应用元数据读取的版本/构建、平台与架构、当前协议版本、仓库/许可证/第三方说明入口，以及测试构建不等于正式发布的说明。

关于页面不得显示配对码、IP、USB/显示器标识、本机路径、证书或个人环境信息。本任务不修改版本号。

## 本机逻辑数据结构 v3

平台可以采用符合原生生态的编码键名，但字段语义必须一致。以下结构只保存在本机，不进入 `contracts/` 或网络消息。

### 顶层字段

| 字段 | 类型 | 必填 | 范围与默认 |
| --- | --- | --- | --- |
| `schemaVersion` | integer | 是 | 固定为 `3` |
| `localDeviceName` | string | 是 | 1...32 个可见 Unicode 字符；新安装为“本机” |
| `listenPort` | integer | 是 | `1...65535`；新安装为 `49731` |
| `displays` | array | 是 | 可以为空 |
| `collaborationProfiles` | array | 是 | 至少一个；新安装含一个空配置 |

### `displays[]`

| 字段 | 类型 | 必填 | 范围与缺少行为 |
| --- | --- | --- | --- |
| `id` | UUID string | 是 | 本机稳定且唯一 |
| `name` | string | 是 | 去除首尾空白后 1...64 个可见字符 |
| `localInput` | integer/null | 是 | `null` 或 `0...65535`；不得猜测 |
| `readEnabled` | boolean | 是 | 新显示器默认 `false` |
| `brightnessEnabled` | boolean | 是 | 新显示器默认 `true` |
| `contrastEnabled` | boolean | 是 | 新显示器默认 `true` |
| `volumeEnabled` | boolean | 是 | 新显示器默认 `true` |

平台原生 selector、后端和兼容路径字段继续保存在本机平台结构中；未知字段按平台兼容规则处理。

### `collaborationProfiles[]`

| 字段 | 类型 | 必填 | 范围与默认 |
| --- | --- | --- | --- |
| `id` | UUID string | 是 | 本机稳定且唯一 |
| `name` | string | 是 | 1...32 个可见字符；忽略大小写后唯一 |
| `peerHost` | string | 是 | 空表示未配置；非空最长 253 字符 |
| `peerPort` | integer | 是 | `1...65535`；默认 `49731` |
| `pairingCode` | string | 是 | 空或至少 8 个字符；不得记录到日志 |
| `coordinationEnabled` | boolean | 是 | 默认 `false` |
| `displayInputs` | array | 是 | 可以为空 |
| `triggerDevices` | array | 是 | 可以为空；只含本机私有引用 |

### `displayInputs[]`

| 字段 | 类型 | 必填 | 范围 |
| --- | --- | --- | --- |
| `displayID` | UUID string | 是 | 引用 `displays[].id` |
| `peerInput` | integer | 是 | `0...65535` |

同一配置内 `displayID` 不得重复。引用已删除显示器的孤立映射应保留为不可用项并提示用户处理，不得自动绑定到新显示器。

### `triggerDevices[]`

| 字段 | 类型 | 必填 | 范围 |
| --- | --- | --- | --- |
| `kind` | string | 是 | `usb` 或 `bluetooth` |
| `localReference` | platform-local value | 是 | 只在本机持久化，不进入公共样例或日志 |
| `displayName` | string | 是 | 本机 UI 名称，不作为稳定身份 |

## 迁移与失败安全

### macOS v2 到 v3

- v2 `macInput` 原值迁移到全局显示器 `localInput`。
- 为旧对端创建一个配置；v2 `windowsInput` 原值按显示器 ID 写入该配置的 `peerInput`。
- 旧 peer host、port、pairing code、USB 触发和协同开关迁入该配置；名称默认“Windows”。
- v1 数组和更早旧键按现有映射直接生成 v3，原数据继续保留。

### Windows v2 到 v3

- 全局显示器 `localInput = null`，不得猜测。
- 为旧对端创建一个配置；v2 `MacInput` 原值按显示器 ID 迁移为 `peerInput`。
- 旧 peer host、port、pairing code、USB 触发和协同开关迁入该配置；名称默认“Mac”。
- `readEnabled` 迁移为 `true`，三个控制功能开关迁移为 `true`；读取失败仍按安全降级处理。

### 共同失败规则

- 只有完整 v3 文档编码、原子写入和回读验证全部成功后才完成迁移。
- 失败时保留原 v2/v1/旧键，持久进入不执行 DDC、USB/蓝牙、唤醒和网络协同的用户检查状态。
- 未知 `schemaVersion`、非法类型、重复 ID、多个同名配置或非法范围安全拒绝；不得选择第一项或覆盖原数据。
- v3 未知字段忽略；已知字段缺少或类型错误不得用硬件探测结果猜测修复。
- 只有用户成功保存完整配置后才能解除持久安全状态。

## 平台任务边界

### Windows

- 实现本机 schema v3、多协同配置和显示器目录分离。
- 增加 Dxva2/ControlMyMonitor 后端接口、三项 DDC 控制、回读、缓存和联动。
- 增加 USB 学习、协同页面和关于页面。
- 不新增切换到本机；菜单使用配置名称。
- 不修改共享协议；网络新行为等待 DS-005 批准。

### macOS

- 实现本机 schema v3、多协同配置和显示器目录分离。
- 移除切换到本机；菜单使用配置名称。
- 对齐 DDC 后端能力/取消/失败隔离接口，保留 USB 学习和关于页面。
- 增加 Dell 全零模拟回归；原生接口准确性继续列为待授权实机验证。
- 不修改共享协议；网络新行为等待 DS-005 批准。

## 安全、隐私和实机边界

- IP、配对码、显示器/USB/蓝牙标识、设备路径和本机路径只能保存在本机，不得进入网络同步、公共向量、日志、提案实例或 Git。
- 配对码不得显示在检测结果、菜单、关于页或日志中。
- 未经用户在当前任务再次确认，不执行真实 DDC 写入、输入源切换、USB/蓝牙交接、唤醒或系统网络修改。
- Dell 原生 DDC 回读属于只读实机验证，但执行前仍需用户确认目标、命令、预期输出和停止条件；记录必须脱敏。

## 回滚

- 两个平台独立实现和回退。
- 回退 v3 代码前必须恢复 v2 备份或执行经过验证的显式反向转换；不得自动删除 v3 配置。
- 本提案不修改 `PROTOCOL.md` 或公共 contracts。
