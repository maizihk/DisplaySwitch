# DS-004：显示控制与手动切换入口对齐提案

- 状态：DRAFT（等待用户批准详细行为）
- 功能编号：DS-004
- 任务类型：cross-platform
- 基线：`24a4ed7bbfab0eb9726ed6261afe5ad56e3f4df7`
- 网络协议：保持 `version = 1`
- 公共 contracts：保持 `schemaVersion = 1`
- Windows 本机配置：建议由 `schemaVersion = 2` 升至 `schemaVersion = 3`
- macOS 本机显示器配置：建议由 `schemaVersion = 2` 升至 `schemaVersion = 3`

用户已于 2026-08-27 决定：Windows 补齐亮度、对比度和音量调节；每个平台只保留一个“切换到对端”手动入口；本机和对端名称可在设置中自定义；Windows 补齐 USB 学习和关于页面。该决定确定产品方向，但平台实施须等待本提案的详细行为获批并进入共享基线。

## 当前行为

### macOS

- 菜单当前同时提供“切换到 Mac”和“切换到 Windows”；用户要求移除“切换到 Mac”，只保留切换到对端。
- 每台显示器提供亮度、对比度和音量滑块，并可选择“联动所有显示器”。
- 使用 VCP `0x10`、`0x12`、`0x62` 读写数值；输入源使用 `0x60`。
- 读取失败时可显示本机缓存估计值；三项读取结果同时为零时按异常回读处理。
- 一台 Dell 显示器此前通过 `m1ddc` 出现“调用成功但三项全零”的不可信回读；切换到原生接口后尚未完成该显示器的实机准确性验证，不能声明问题已经解决。
- 设置页可以学习 USB 设备，并已有关于页面。
- 配置安全状态会阻断 DDC、USB、唤醒和网络副作用。

### Windows

- 托盘当前只有“手动切换到 Mac”，方向上已经符合“只切换到对端”，但名称被硬编码。
- 每台显示器只保存 Mac 输入源，没有 Windows 输入源。
- 原生 Dxva2 与 ControlMyMonitor 当前只用于写入输入源 `0x60`，没有产品化的亮度、对比度、音量读写入口。
- 设置页只能枚举并选择当前 USB 设备，不能通过一次插拔变化学习触发设备。
- 设置窗口没有关于页面。
- Windows 本机设置文档当前为 `schemaVersion = 2`。

## 建议的公共用户行为

### 1. 手动切换入口

每个平台菜单或托盘只显示一个手动入口：`切换到 {对端名称}`。

共同语义：

1. macOS 移除“切换到本机”入口；Windows 不新增“切换到本机”入口。
2. 入口标题由设置中的 `peerDeviceName` 生成，不得硬编码 Mac 或 Windows；修改名称后菜单立即更新。
3. 手动入口只执行本机 DDC 对端输入源写入，不创建交接 `eventID`，不发送 UDP，不改变 USB 状态，不唤醒显示器，也不改变交接状态机。
4. 使用每台显示器配置的 `peerInput`；不得根据操作系统、枚举顺序或其他显示器猜测输入值。
5. 缺少 `peerInput` 的显示器不执行写入；其他配置完整的显示器仍可独立完成，最终明确报告部分失败。
6. 如果没有任何显示器可以执行，保持零硬件副作用并提示完成配置。
7. 配置处于安全状态时入口不得执行 DDC；平台应显示需要用户检查配置的原因。
8. 一次手动切换未结束时不能重复触发，完成或取消后恢复。
9. 每台目标显示器首次写入失败时可在 150 ms 后重试一次。单台失败不得阻止其他显示器；不得对一次点击无限重试。

两端 UI 可以使用平台原生菜单实现，不要求像素级一致。

### 2. 自定义设备名称

两端设置页都提供：

- `本机名称`：`localDeviceName`
- `对端名称`：`peerDeviceName`

共同规则：

1. 名称去除首尾空白后必须为 1 至 32 个可见 Unicode 字符，不允许换行和控制字符。
2. 新安装使用中性默认值“本机”和“对端”，不猜测操作系统、电脑型号或用户名。
3. 从旧配置迁移时，为保持现有显示，可按当前平台写入旧称：macOS 为“Mac”/“Windows”，Windows 为“Windows”/“Mac”；用户之后可以修改。
4. 名称只用于本机 UI、状态文本和输入源字段标签，不进入 UDP 消息、公共 contracts、日志或公共测试数据。
5. 显示器输入源在 schema v3 中使用角色名称 `localInput` / `peerInput`；不能根据自定义名称推断数值。
6. 自定义名称不改变 UDP v1 的 `source` / `target` 枚举。当前 v1 网络协同仍是 `mac` 与 `windows` 两种固定角色；两台 Mac 或两台 Windows之间的网络协同不在本提案范围，需要另行设计协议版本和角色兼容策略。

### 3. 亮度、对比度和音量

两端均按显示器提供以下逻辑控制：

| 控制 | VCP code | 用户值 |
| --- | --- | --- |
| 亮度 | `0x10` | `0...有效最大值` |
| 对比度 | `0x12` | `0...有效最大值` |
| 音量 | `0x62` | `0...有效最大值` |

共同语义：

1. 控件按稳定显示器身份关联，不依赖 `DISPLAY1` / `DISPLAY2` 或枚举顺序。
2. 用户可以调节单台显示器，也可以显式启用“联动所有显示器”；默认不得暗中联动。
3. 滑块仅在用户提交一次变更时写入，拖动预览不得造成无界连续 DDC 写入。
4. 读取成功时显示当前值；报告的最大值必须至少为 10 且不小于当前值，否则显示范围使用 `max(100, current)`。
5. 某台显示器三项控制均成功读取为 `0` 时，按异常遥测处理，不用这些结果覆盖缓存或 UI；单独一项为零仍可视为合法值。
6. 读取失败时不写硬件。存在该显示器对应控制的本机缓存时可显示为估计值；没有缓存时显示未知，不猜测当前值。
7. 写入成功后才更新该显示器的本机缓存。失败时保留上次成功值并报告具体显示器和控制项。
8. 某台显示器或某项 VCP 不支持时只影响该显示器/控制项，不得操作其他硬件标识。
9. 配置安全状态统一阻断读取、写入、枚举刷新引发的后续硬件动作以及缓存提交。

### 4. USB 设备学习

两端设置页都提供“学习 USB 设备…”：

1. 开始学习时记录当前 USB 设备集合，提示用户操作一次 USB 切换器。
2. 只把学习期间新增或消失的设备作为候选，显示脱敏的本机名称并由用户明确选择；不得自动选择第一个设备。
3. 学习期间暂停该学习会话产生的自动交接动作，不发送 UDP，不执行 DDC 或唤醒。
4. 学习窗口为 30 秒；用户取消、设置窗口关闭、配置重载或超时后停止学习并丢弃候选，不改变已保存设备。
5. 没有唯一变化时显示候选列表或要求重试，不猜测 USB Hub。
6. Windows 可以继续保留“刷新并选择当前设备”作为辅助入口，但不能以它代替学习功能。
7. USB 原始标识、序列号和设备路径只保存在本机；测试、日志、提案和 handoff 只能使用脱敏值。

### 5. 关于页面

Windows 设置增加与 macOS 对等的“关于”页面，至少显示：

- 产品名称和从应用元数据读取的当前版本/构建信息；本任务不修改版本号。
- 当前平台与架构。
- 网络协议 `version = 1`。
- 项目仓库、许可证和第三方组件说明入口。
- “自动测试/未签名构建不等于正式发布”的说明。

关于页面不得显示配对码、IP、USB/显示器标识、本机路径、证书、Team ID 或其他个人环境信息。macOS 保留现有关于页面，并核对同一组公共信息，不要求像素级一致。

## DDC 后端共同逻辑接口

平台内部语言和类型可以不同，但应能映射到以下逻辑操作：

- `enumerate() -> [display]`
- `availability(display, control) -> available | unsupported | temporarilyUnavailable`
- `read(display, control) -> current + optionalMaximum | error`
- `write(display, control, value) -> success | error`
- `cancel(operation)`

共同要求：

- `control` 至少包含 `input`、`brightness`、`contrast`、`volume`。
- 原生后端和兼容后端是独立实现；选择或回退后端不得改变控制语义。
- Windows 原生后端使用系统物理显示器 API；ControlMyMonitor 可以使用其 `/SetValue` 和 `/GetValue` 能力。无法可靠获得最大值时按上述有效最大值规则降级。
- macOS Apple Silicon 原生后端和 `m1ddc` 回退保持现有选择策略；Intel Mac 无可用后端时明确报告不支持。
- 所有异步操作在 App 退出、配置重载或进入安全状态后必须可取消或丢弃迟到结果。

## 本机数据结构

本功能不创建跨端配置同步，也不把平台配置写入 `contracts/`。

### Windows `schemaVersion = 3`

顶层新增字段：

| 字段 | 类型 | 必填性 | 合法范围 | 缺少时行为 |
| --- | --- | --- | --- | --- |
| `LocalDeviceName` | JSON string | v3 保存时必填 | 去除首尾空白后 1...32 个可见 Unicode 字符 | v2 迁移为“Windows”；全新安装为“本机” |
| `PeerDeviceName` | JSON string | v3 保存时必填 | 去除首尾空白后 1...32 个可见 Unicode 字符 | v2 迁移为“Mac”；全新安装为“对端” |

每个 `Displays[]` 项在现有字段基础上增加：

| 字段 | 类型 | 必填性 | 合法范围 | 缺少时行为 |
| --- | --- | --- | --- | --- |
| `LocalInput` | JSON integer | v3 保存时必填 | `-1` 或 `0...65535` | 从 v2 迁移为 `-1`，表示未配置，禁止猜测 |
| `PeerInput` | JSON integer | v3 保存时必填 | `-1` 或 `0...65535` | 从 v2 的 `MacInput` 原值迁移 |
| `ReadEnabled` | JSON boolean | v3 保存时必填 | `true` / `false` | 从 v2 迁移为 `true` |

- v2 的 `MacInput` 字段语义不变，只在升级到 v3 时明确迁移为角色中性的 `PeerInput`；不得把它迁移为本机输入。
- `LocalInput = -1` 不得阻塞已有“切换到对端”及自动交接；Windows 当前流程不使用本机输入源。
- `ReadEnabled = false` 时不主动读取该显示器的三个数值，但用户明确写入仍可执行。
- 控制缓存仅保存在本机并按稳定显示器 ID 与 VCP code 分隔；不得包含在网络消息或公共样例中。

### macOS `schemaVersion = 3`

文档顶层新增：

| 字段 | 类型 | 必填性 | 合法范围 | 缺少时行为 |
| --- | --- | --- | --- | --- |
| `localDeviceName` | JSON string | v3 保存时必填 | 去除首尾空白后 1...32 个可见 Unicode 字符 | v2 迁移为“Mac”；全新安装为“本机” |
| `peerDeviceName` | JSON string | v3 保存时必填 | 去除首尾空白后 1...32 个可见 Unicode 字符 | v2 迁移为“Windows”；全新安装为“对端” |

- 每台显示器的 `localInput`、`peerInput` 为可缺少的 JSON integer；存在时合法范围是 `0...65535`，缺少表示该方向未配置。
- 每台显示器把 v2 的 `macInput` 迁移为 `localInput`，把 `windowsInput` 迁移为 `peerInput`；`readEnabled` 语义不变。
- 迁移只改变角色命名，不改变任何输入源数值；原 v2 文档必须保留到 v3 原子写入成功。
- macOS 自动交接可以继续使用 `localInput` 和 `peerInput`，但菜单只保留手动切换到 `peerInput` 的入口。

## 迁移、未知字段和失败安全

- Windows 必须读取 schema v2，把 `MacInput` 迁移为 `PeerInput`，并补充 `LocalInput = -1`、`ReadEnabled = true` 和迁移名称；只有完整 v3 文档原子写入成功后才视为迁移完成。
- Windows schema v1/旧双显示器字段先按现有规则恢复原输入值和稳定配置，再直接生成 v3；不得生成中间文件覆盖原始旧数据。
- 迁移写入失败时保留原 v2 文件，不覆盖、不删除；既有 v2 能力不得因新增字段而被错误解释。
- 损坏数据、非法类型或未知 `schemaVersion` 安全拒绝，进入不执行 DDC、USB、唤醒和网络交接的状态。
- v3 未知字段忽略；已知字段类型错误不得用猜测值修复。
- 降级到旧版 Windows 时，旧版会拒绝未知 schema v3 并进入安全状态。因此回滚平台提交前，应恢复用户备份的 v2 设置，或由回滚工具显式去除只属于 v3 的字段并把版本改回 2；不得静默覆盖。
- macOS 必须按相同的原数据保留、原子写入、失败持久安全门和用户成功保存后解除规则迁移到 v3；回退旧版前同样需要恢复 v2 备份或显式反向转换。
- macOS v1 数组和更早的 `Display.1` / `Display.2` 键按现有映射直接生成 v3；原 v1/旧键继续保留。

## 平台任务范围

### Windows

- 实施 DDC 后端逻辑接口，并让 Dxva2 与 ControlMyMonitor 分别适配。
- 增加 per-display 亮度、对比度、音量读取和写入入口，以及显式联动开关。
- 托盘保留单一手动入口，标题改为设置中的对端名称；不得新增切换到本机。
- 本机配置迁移到 schema v3，加入角色中性的本机/对端名称、`LocalInput`、`PeerInput` 和读取开关。
- 增加与 macOS 对齐的 USB 学习流程；保留当前设备枚举选择作为辅助方式。
- 设置窗口增加关于页面。
- 增加无硬件测试，更新 Windows 清单和 handoff。

### macOS

- 将现有 DDCController 映射到共同后端语义，补充可用性、错误、取消和单显示器失败隔离测试。
- 移除“切换到本机”，保留使用自定义对端名称的单一手动入口；核实零网络/USB/唤醒副作用、重复点击保护和安全状态规则。
- 本机显示器配置迁移到 schema v3，使用角色中性的名称和输入字段，不改变输入值。
- 核实 USB 学习和关于页面满足共同语义。
- 为 Dell 全零回读增加模拟回归；原生接口准确性保持“待授权实机验证”，不得仅凭后端切换标记完成。
- 不改变现有 AppKit UI 技术栈。
- 更新 macOS 清单和 handoff。

## 安全与隐私

- 自动测试和公共样例不得包含真实 IP、配对码、显示器 UUID、USB ID、设备路径或本机路径。
- 日志不得记录原始硬件标识、路径或控制值之外的个人配置；配对码始终禁止记录。
- USB 学习的自动测试必须使用模拟设备集合；不得把个人 USB 信息写入测试或提交。
- 真实 DDC 写入可能改变亮度、音量或造成黑屏。未经用户在当前任务再次明确确认，平台 Agent 不得执行实机写入、输入源切换、USB 交接或唤醒测试。
- Dell 原生回读验证属于读取型实机测试，但可能唤起后端和访问个人硬件；执行前仍需用户确认目标显示器、只读命令、预期输出和停止条件，结果必须脱敏。

## 实现依据

- Microsoft Win32 物理显示器 API：[`GetVCPFeatureAndVCPFeatureReply`](https://learn.microsoft.com/windows/win32/api/lowlevelmonitorconfigurationapi/nf-lowlevelmonitorconfigurationapi-getvcpfeatureandvcpfeaturereply) 与 [`SetVCPFeature`](https://learn.microsoft.com/windows/win32/api/lowlevelmonitorconfigurationapi/nf-lowlevelmonitorconfigurationapi-setvcpfeature)。Microsoft 明确提示不同显示器对 MCCS/DDC 的实现可能不完整，因此失败隔离和实机兼容性验证不能省略。
- ControlMyMonitor 官方命令行说明：[`/GetValue`、`/SetValue` 和导出命令](https://www.nirsoft.net/utils/control_my_monitor.html)。兼容后端不得把进程启动成功误判为显示器必然支持对应 VCP code。

## 回滚

- 两个平台以独立提交实现，可分别回退。
- 回退任一平台 v3 实现前必须处理本机 v3 配置兼容问题；代码回退本身不得自动删除用户配置。
- 本提案不修改 `PROTOCOL.md` 或公共 contracts，回滚不涉及网络协议。
