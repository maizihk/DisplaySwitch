## 根因与修复

- `EnabledCompleteProfiles()` 正确要求已启用且已绑定 `peerEndpointID`，但监听和首次空目标探测也错误地只从该集合取候选，使持久的未绑定配置永远无法令 Windows 启动监听；只有 Windows 自己执行检测时临时 draft 才能响应，因而出现 Windows→macOS 可检测而 macOS→Windows 无响应。现保留正常集合的严格条件，新增仅用于 bootstrap 的未绑定候选和监听端口判定；候选要求 endpoint 为空、协议为空或 v2、host/port/配对密码和本机基础映射完整，且不要求或自动改变协同启用状态。
- 第一版把“请求方 `sourceEndpointID` 已存在于绑定配置”直接当成 `EndpointConflict`，误拒绝了 Windows 已绑定 Mac、Mac 尚未绑定 Windows 的合法非对称 bootstrap。现先按 source endpoint 查找绑定关系：唯一精确绑定继续验证 host、来源端口和 HMAC 后响应；同一 endpoint 重复绑定仍拒绝。没有精确绑定时保留双方未绑定候选，同时把同一来源与凭据却声称新 endpoint 识别为身份冲突。
- 空目标 `status_probe` 成功响应保持同一 `eventID` 并定向请求方，不修改、保存或重新绑定 endpoint。请求方等于本机、重复绑定、身份变化、零/多候选、错误端口、错误 HMAC、未知协议、非法消息及 nonce 重放冲突均零回复；完全相同的合法重复消息仍遵循协议只允许复用响应，不进入正常状态机，也不执行 USB、唤醒或 DDC。
- 原生枚举原先把同一系统物理接口返回的每个 `PHYSICAL_MONITOR` 句柄分别追加为配置项，并使用接口加下标作为 ID；设置页又只追加不删除，因此重复句柄、断开项和通用“显示器 1/2/3”名称会持续累积。
- 现在按稳定物理接口合并候选句柄；只有完整、可信且非空的枚举快照才协调实时集合并清理断开显示器及孤立映射。部分失败、空集合、短暂断开或休眠会保留全部显示器配置、USB 映射和协同映射。
- 仍连接或休眠后恢复的显示器保持逻辑 ID、用户名称、DDC 功能开关、托盘开关、输入源和缓存。旧的带下标原生 ID 在本机规范化匹配，不改变 schemaVersion 5。
- 设置页、USB 映射和托盘使用用户名称或 Windows 友好名称；同型号按稳定本机 ID 排序生成序号。原始硬件标识只留在本机配置，不写日志或交接。
- DDC 偶发失效路径原先存在多线程同时枚举/操作 Dxva2 句柄、枚举失败退化为空集合、固定 150 ms 外层重试，以及 `auto` 控制通道可能选择 CMM 的混合语义。现在 Dxva2 获取、VCP 调用和释放串行化；同一接口的候选句柄有界尝试并统一释放；枚举/读取/写入失败明确返回。只有明确失败才重新枚举一次，不在成功后重试，也没有固定 sleep 或无限重试。
- W-009 正式运行时只选择原生 Dxva2。ControlMyMonitor 源码和兼容配置字段没有删除，但原生不可用时绝不调用它。
- USB 学习原先永久排除学习开始时已存在的引用。现在跟踪“曾离开”的基线设备，使其重新接入时成为候选；候选确认前仍保持零网络和硬件副作用。
- USB 触发不稳定的根因是所有设置保存都重建协调器并清空存在基线，而设备通知后的单次快照又可能早于 PnP 状态落定。现在相同 USB 绑定下只修改联动协同、显示器映射或其他设置时保留基线；更换设备、启停 USB 自动切换、学习结束或安全状态变化仍会重建基线。
- 设备通知后新增 1 秒、100 ms 间隔的有界复查窗口，以捕获延迟落定的离开/接入状态；稳定后恢复原有低频后备轮询，没有添加无界重试或 DDC sleep。
- 第一轮列对齐仍让表头和各控制行使用独立 Grid，列宽虽然相同，但布局测量彼此独立，且 72 px 标签列不足以容纳“对比度”，实机仍可见错位。现改为表头与亮度、对比度、音量三行共用一个 Grid 和同一组列定义，标签列扩为 96 px；功能、托盘、滑杆和值均落在统一列线上。
- 普通设置页不再使用 `ToggleSwitch.Header` 的纵向“名称、开关和开/关文字”模板；登录启动、USB 自动切换、联动协同、联动显示器和协同配置启用均改为左侧名称、右侧纯滑块开关的单行布局，并保留自动化名称和原即时保存行为。
- 右侧大间距的最终根因不是父级宽度，而是 WinUI `ToggleSwitch` 默认约 154 个逻辑像素的最小宽度：清空开/关文字后，文字区仍透明占位，可见滑块位于控件左侧。现将单行开关 `MinWidth` 设为 0，使可见滑块贴到控件右边界；此前为排查加入的标签页、卡片和分区拉伸改动已撤回，避免无关布局变化。
- 最后剩余的左右边距差来自分区额外 20 px 右内边距和开关模板的内容间隔。现移除单侧分区内边距，并把无文字开关固定为标准 40 px 轨道宽度，使可见轨道按卡片统一内边距靠右。
- USB 页把当前设备选择、学习按钮和连接状态移动到“USB 自动切换”正下方；界面仅保留“学习 USB 设备…”按钮，移除“重新读取”和“清除当前设备”。启动枚举、配置加载、设备选择、学习及 USB 触发逻辑保持不变。
- USB 页将“联动目标配置”简化为“联动目标”，并与下拉框同一行；显示器名称分别与输入源文本框同一行，“USB 离开后切到的输入源”改为只显示一次的分组说明。原校验、即时保存和稳定显示器 ID 关联保持不变。
- USB 页进一步将“联动目标”标签、目标配置下拉框和“联动协同”开关合并为同一行；开关自动化名称仍为“联动协同”，目标选择、启用校验和即时保存行为不变。
- USB 页将“USB 触发设备”标签、设备下拉框、学习按钮和短状态合并为同一行；状态简化为“（未选择）”“（已连接）”或“（未连接）”，学习流程的长提示继续显示在验证区域。分区标题相应改为“USB 切换”。
- USB 主区域按用户表格进一步收敛：“USB 自动切换”简化为“自动切换”，“USB 触发设备”简化为“触发设备”，设备行顺序为下拉框、状态、短“学习”按钮；输入源分组简化为“对端输入源”，每台显示器使用左侧名称和右侧 120 px 输入框。DS-008 要求的联动目标与开关保留并移到输入源之后。
- 协同配置编辑器采用同一紧凑规则：配置名称、输入框和启用开关同一行；对端地址、地址输入框、端口标签和端口框同一行；配对密码标签与输入框同一行；“显示器输入映射”简化为“对端输入源”，每台显示器名称靠左、输入源使用右侧 120 px 文本框。字段校验、即时保存、检测和排序删除行为不变。
- 关于页原先通过 `BitmapImage` 直接加载多尺寸 ICO，WinUI 选择较小图层后放大，导致 72 px 显示发糊。现从同一项目图标的 256×256 PNG 图层生成专用 `AppIcon-256.png`，关于页明确加载该资源；窗口、任务栏和托盘继续使用原多尺寸 ICO。
- Windows 用户可见的“配对码”已统一改为“配对密码”，包括设置标签、认证失败提示和配置校验提示；内部 `pairingCode` 成员、磁盘配置字段及协议字段保持不变，避免破坏兼容性。
- “当前配置”组合框使用 WinUI `Header` 后整体高度包含标题和输入框，而相邻按钮默认按整个控件高度布局，导致按钮悬在两者之间。现将“添加配置”按钮与组合框底边对齐，使其和实际下拉框处于同一水平行。
- 五个设置标签页移除与顶部标签重复的外层卡片标题；“对端输入源”等实际内容分组标题继续保留。
- 启动闪窗来自生命周期窗口先 `Activate()` 再 `Hide()`。现保持该窗口从创建开始不激活、不显示：本机配置文件不存在时由 Controller 显式打开设置窗口；已有配置的后续启动只驻留托盘，不显示任何窗口。
- USB 物理切换延迟的主要代码原因是通知后的快速复查仅持续约 1 秒，随后回落到 2 秒后备轮询；Hub 的 PnP 状态若晚于快速窗口落定，就会出现明显空档。现在精确匹配所选设备实例的移除/接入通知可直接提交对应状态，无关设备通知不会触发；明确通知后的 1.5 秒内忽略相反的陈旧枚举结果。无法精确匹配的通知使用 100 ms 快速复查后接续 250 ms 确认，不再出现 2 秒断层。
- USB 通知回调只更新内存状态和唤醒工作线程；诊断日志移动到状态及 DDC 调度之后，避免文件 I/O 位于切换关键路径。
- 新版仍有约 2 秒延迟时，继续审计到 DDC 下游：一次多显示器切换虽然并发投递，但原生 Dxva2 由互斥锁串行执行，且此前每台显示器写入都会重新枚举并持有全部物理显示器句柄，导致枚举成本按显示器数量重复。现在同一批切换共用一次原生枚举快照，按稳定逻辑 ID 复用对应句柄；单项失败会立即丢弃快照，使既有的一次刷新重试仍重新枚举，不增加 sleep、无限重试或 ControlMyMonitor 回退。完成日志增加不含硬件标识的 `duration_ms`，用于区分通知延迟与 DDC 执行耗时。

- 实际两台显示器是否只枚举两项，以及 Windows 友好名称和同型号本机序号是否符合预期。
- 原生 Dxva2 亮度、对比度、音量的连续读取/提交，单台失败隔离和句柄重建。
- 输入源切换是否稳定响应；失败提示是否准确，且不会调用 ControlMyMonitor。
- USB 学习开始前已连接设备的离开、重新接入、多候选选择、取消和超时交互。
- 设置页/托盘名称、实时增删、高 DPI 和窄窗口交互。
- 本任务未启动正式程序，未执行真实 UDP、USB、DDC、显示器唤醒、输入源切换、防火墙或系统设置操作。
