## 公共行为定义

DS-001 不新增用户功能，也不改变现有协议 v1 的消息字段、端口、正常交接顺序或超时时序。目标是把现有协议中的共同要求变成两端都可用模拟时间和模拟硬件验证的状态机行为：

1. 非法、过期、未知版本、错误方向或认证失败的消息不得刷新对端在线状态，也不得触发唤醒、USB、DDC 或状态机迁移。
2. 合法消息可刷新对端在线状态；`status_probe` 必须以相同 `eventID` 回复 `status_response`，且状态探测不得产生硬件动作。
3. 在线源端按 150 ms 间隔最多发送 4 次 `handover_request`，并在 600 ms 后兜底；离线源端发送一次后立即切屏。
4. 重复请求不得重复唤醒或切屏，但目标端可以为当前同一事件重新发送确认，以容忍确认丢包。
5. USB 在等待期间回到源端时取消当前交接；旧事件的确认或提交不得影响新事件。
6. `usb_present` 表示物理 USB 已到达目标端，可以完成源端当前仍在等待的交接；其事件 ID 不要求等于源端尚未被目标端获知的事件 ID。
7. 迁移或验证失败时进入不执行硬件动作的安全状态。

详细规范、兼容策略和测试样例见已批准提案。提案批准授权协调 Agent 创建公共 contracts，但在协调 PR 合并前仍不授权平台修改行为。

## 公共测试向量

协调 Agent 已在 `contracts/protocol-v1/` 创建公共 schema 和测试向量，当前包含 17 条消息验证向量与 16 条状态机向量，覆盖：

- 合法消息与六种消息类型。
- 缺失字段、错误字段类型、未知字段、未知消息类型和未知版本。
- 非 UUID `eventID`、错误 source/target、错误配对码、过期及未来超窗时间戳。
- 十秒有效期边界。
- 重复、乱序和跨事件的迟到确认。
- 150 ms 防抖、4 次请求重发、600 ms 兜底、6 秒在线窗口。
- USB 返回取消、USB 先到、请求先到、确认丢包和对端离线。
- `status_probe/status_response` 的相同 `eventID`、重复 probe 跨过六秒在线窗口后的恢复，以及零硬件副作用。

向量只使用固定测试 UUID、示例配对码、相对时间和逻辑端点，不包含真实设备或网络信息。`python3 contracts/protocol-v1/validate.py` 必须在协调提交前通过；两端需同步本协调提交并证明 16 条状态机向量均由原生测试消费。

## 当前已发现差异

已审计的实现差异均已在各平台 PR 中修复。最后发现的重复合法 `status_probe` 行为现已统一为：跨过六秒在线窗口后恢复在线、回复相同 `eventID`，且不产生拒绝动作或硬件副作用。剩余验收项是两端同步本协调提交并共同通过新增 `SM-016`。
