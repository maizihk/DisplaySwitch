## 公共行为定义

本任务只把现有 Windows 构建、自动测试和绿色版产物检查搬到 GitHub 托管的 Windows runner。不得改变应用运行时、协议字段、配置语义、硬件行为或 macOS 实现。

CI 必须在全新 runner 和空项目缓存条件下完成：

1. 检出仓库并使用只读仓库权限。
2. 使用支持 Visual Studio 18 和 `v145` 的 GitHub 托管 Windows x64 runner。
3. 恢复 C++/WinUI 3 项目依赖。
4. 构建 Windows Native、Launcher 和 Tests 的 x64 Release。
5. 执行无硬件自动测试，并明确通过 17 条消息向量和 16 条状态机向量。
6. 运行现有 `Windows/build-windows.ps1` 生成 `Windows/dist/`。
7. 验证根入口、`runtime/` 必需文件和小于 20 MiB 的现有体积限制。
8. 上传未签名、framework-dependent 的 Windows x64 测试 artifact；不得提交构建产物。

## Runner 与工具链决定

三个正式 Windows 工程当前都声明 `MinimumVisualStudioVersion = 18.0` 或 `PlatformToolset = v145`。因此 workflow 应显式使用 GitHub 官方提供的 `windows-2025-vs2026`，不要依赖会迁移的 `windows-latest`，也不要降级工程工具集来迎合旧 runner。

该 runner 选择只属于 CI 环境，不改变应用最低 Windows 版本或发布依赖。若官方 runner 暂时缺少项目需要的 Visual Studio 组件，平台 Agent 应先记录准确错误并最小化补齐 CI 环境；不得擅自改用旧工具集或修改运行时代码。
