## 排期位置

作为下一项 macOS 开发任务，优先级位于新的功能扩展之前。目标是先让用户能正确完成协同所需的本地网络授权，并避免把“对端无响应”误报为权限被拒绝。

## macOS 任务范围

1. 不新增“授权”标签页；在现有“协同”页顶部增加紧凑的“本地网络权限”模块。
2. 模块说明本地网络仅用于发现并连接局域网中的 DisplaySwitcher 设备。
3. 提供“检测并申请权限”按钮，由用户动作触发真实本地网络操作和系统授权弹窗；不得在首次启动时为了弹窗执行虚假 Bonjour、组播或硬件动作。
4. 权限由 macOS 管理，不提供伪造的 App 内权限开关。
5. 状态文案限制为：
   - `未检测`
   - `协同连接正常`
   - `系统明确拒绝`
   - `连接失败，请检查权限、地址和防火墙`
6. 只有系统返回明确的本地网络拒绝证据时，才能显示“系统明确拒绝”。超时、零响应、发送失败或认证失败不得单独推断为权限被拒绝。
7. 被明确拒绝时，提供前往“系统设置 → 隐私与安全性 → 本地网络”的操作说明；系统设置入口不可用时必须保留纯文字路径。
8. 复核并更新 `NSLocalNetworkUsageDescription`，使其准确描述连接检测、协同唤醒和显示器切换，不暗示跨端同步原始 USB 或硬件标识。
9. 保持当前直接 UDP、固定监听端口、HMAC、重放保护和零硬件副作用检测行为不变。
10. 不改变当前 ad-hoc 签名策略，不引入 Developer ID、公证、App Sandbox 或 Hardened Runtime 工作。

## Windows 任务范围

无。Windows 不修改代码、设置页面、协议、配置或 handoff；该任务不得因 Windows 没有对应权限页面而阻塞。

## 实现结果

- macOS 协同页已经提供紧凑的“本地网络权限”模块和“检测并申请权限”入口，没有新增标签页或 App 内权限开关。
- 入口复用既有绑定端口 UDP 检测；不使用 Bonjour、组播、旁路连接，也不触发 USB、DDC、唤醒或输入源切换。
- 展示模型只允许预定的四类状态；当前 BSD UDP 不能可靠证明 TCC 拒绝，因此普通超时、认证失败和网络错误不会被误报为“系统明确拒绝”。
- 11 项相关测试、118 项当时的完整 XCTest、Debug/Release、打包和严格 ad-hoc 验签通过；后续主线回归继续覆盖该实现。
- 唯一未关闭项是 macOS 15 及以上首次弹窗、允许、拒绝和在系统设置中重新允许后的真实 TCC 行为。

## 自动测试要求

- 使用纯状态或展示模型覆盖四种允许显示的状态及状态转换。
- 明确拒绝、普通网络错误、超时、认证失败和成功响应必须映射到不同结果，不得误报权限。
- “检测并申请权限”测试使用模拟网络接口，不访问真实局域网，不弹系统授权框。
- 状态更新不得触发 USB、DDC、显示器唤醒或输入源切换。
- 既有 v2 协同、固定源端口和公共测试向量继续通过。

## 实机验证

- 在 macOS 15 及以上确认首次用户操作能出现本地网络授权框。
- 分别验证允许、拒绝、在系统设置中重新允许后的恢复行为。
- 验证错误 IP、对端未启动、防火墙阻断和配对码错误不会显示“系统明确拒绝”。
- 实机验证不得修改防火墙规则；只观察现有系统状态和用户手动权限选择。

## 未解决问题

- 当前直接 UDP 实现能否稳定获得 macOS 明确的本地网络拒绝错误，需要平台实现前用公开系统 API 验证。若无法可靠区分，界面只显示“未检测 / 协同连接正常 / 连接失败”，不得通过旁路探测伪造授权状态。
