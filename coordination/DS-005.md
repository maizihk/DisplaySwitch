## 公共行为

1. 手动选择配置时，只请求该 endpoint 唤醒和确认，再执行该配置的显示器映射。
2. 自动切换且只有一个已开启配置时，直接与唯一目标协同。
3. 多个配置同时开启时进入 3 秒发现窗口，首个通过认证的合法 `input_present` 立即且不可变地锁定目标，不设置仲裁窗口。
4. 发现超时不猜测目标、保持零 DDC，并提示用户手动选择。
5. 配置检测只确认版本、endpoint 和认证能力，不触发 USB、蓝牙、唤醒或 DDC。
6. 首次或变化的 endpointID 必须由用户确认，不能自动保存或替换。

## 协议和公共数据状态

- `PROTOCOL.md` 已通过 PR #31 纳入完整 v2 规范，并保留 v1 兼容语义。
- v2 使用随机逻辑 endpointID，不依据平台名称、硬件标识或枚举顺序判断身份。
- PBKDF2-HMAC-SHA256 固定为 200000 次、32 字节发送方向密钥；配对码不进入网络消息。
- nonce 为 16 个安全随机字节，重放缓存至少 20 秒；认证标签使用常量时间比较。
- v1/v2 按 `version` 进入独立解析器和状态机；v2 行为不编码为 v1 消息。
- `schemaVersion = 3` 只保存本机配置，不同步 IP、配对码、USB/蓝牙或显示器硬件信息。

## 兼容、迁移和降级

- v1 保持已发布字段、时序和单目标 USB 交接语义。
- `仅 v1` 配置不参与 v2 手动唤醒、蓝牙声明、同系统协同或多目标发现。
- 多候选、认证失败、未知版本、错误 endpoint、发现超时或配置变化时保持当前显示器状态，不猜测目标。
- 配置迁移失败继续保留原数据并进入零硬件副作用的安全状态。
- 回退 v2 实现不得删除 schema v3 本机配置，且不影响本机显示器控制。
