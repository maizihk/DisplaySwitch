# DS-004 跨平台功能对齐审计

- 功能编号和名称：DS-004 跨平台功能对齐审计
- 任务类型：coordination-only（后续可拆分 cross-platform、windows-only 和 macos-only 实施任务）
- 当前状态：DRAFT
- 当前基线：`1ba6ae21bda4b0fb9355d9a04bd81f2e18b09c64`

## 目标和边界

核对 macOS 与 Windows 当前真实实现，区分必须完全一致的公共行为、语义应一致但实现可不同的能力、合理的平台差异以及需要用户决定的产品范围。

本审计不要求两端复制相同 UI，不修改平台代码、handoff、开发清单、`PROTOCOL.md`、contracts、GitHub Actions、Release、tag 或版本号，也不执行真实 USB、DDC、显示器唤醒或防火墙操作。

## 协议和公共数据状态

- 网络协议：`version = 1`，不变。
- 公共 contracts：`schemaVersion = 1`，不变。
- 已批准 proposal：`specs/proposals/DS-001-protocol-v1-state-machine-conformance.md`。
- 公共向量：17 条消息验证向量、16 条状态机向量，两端均已接入。
- DS-004 当前不提出网络字段或已发布数据语义变化。

## 审计发现的记录差异

1. `macOS/DEVELOPMENT_CHECKLIST.md` 的 M-004 复选框仍未勾选，但 `handoffs/macos.md`、合并提交、公共向量测试和 GitHub CI 均证明实现已完成。这是 macOS 记录漂移，不是代码缺失。
2. `handoffs/windows.md` 仍写 PR #9 “保持未合并”，但 PR #9 已合并为 `71df0e7c018aba18e33bf3363173e1df255323e3`，随后主线 Windows CI 已通过。这是 Windows handoff 记录漂移。
3. 当前没有开放 PR；`main` 已同时包含两端 DS-001 实现、Windows CI 和跨平台 README。

平台 Agent 必须自行更新本平台清单和 handoff；协调 Agent 不代填或修改。

## 推荐实施顺序

### 第一阶段：恢复事实一致性和配置安全

1. macOS Agent 更正 M-004 清单状态和 handoff 当前基线，只记录真实已完成项。
2. Windows Agent 更正 W-004 handoff 的合并状态和最终 main CI，只记录真实事实。
3. 派发 macos-only 配置安全任务：为当前显示器配置增加显式 `schemaVersion` 包装、兼容读取 v1 数组、原子迁移、失败保留原数据并停用自动硬件动作，以及无硬件失败路径测试。

第三项不改变网络协议或公共数据语义，Windows 已有等价安全行为，因此 Windows 不应被阻塞。

### 第二阶段：共同能力语义

1. 起草跨平台诊断提案，定义允许公开的逻辑字段、`schemaVersion`、脱敏规则、预览和安全失败行为；禁止原始 IP、UUID、USB ID、配对码和本机路径进入公共诊断样例。
2. 定义 DDC 后端共同能力语义：枚举、可用性、读取、写入、错误、取消和单显示器失败隔离。接口语言和具体后端保持平台原生。
3. 两端分别实施 M-005/M-006 与 W-201/W-203，不让平台私有代码修改共享文件。

### 第三阶段：产品范围和首次引导

1. 用户决定 Windows 是否需要与 macOS 对齐亮度、对比度、音量和回读控制。
2. 基于已稳定的配置、DDC 能力和诊断字段设计两端首次运行安全引导。
3. 正式签名/安装和协议 v2 分别另立任务，不混入功能对齐实现。

## 兼容、迁移和降级策略

- DS-004 审计本身不改变运行时数据，无迁移。
- 未来 macOS 配置安全任务必须读取现有 `Displays.Configuration.v1` 数组，成功后原子写入带 `schemaVersion` 的新结构；失败时保留原数据并停用自动硬件动作。
- 未知配置版本必须安全拒绝，不能猜测字段语义或覆盖用户配置。
- 平台专有后端不可用时应报告可用性并安全降级，不得误操作其他显示器。
