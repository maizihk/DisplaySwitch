# DS-004 跨平台功能对齐

- 功能编号和名称：DS-004 跨平台功能对齐
- 任务类型：cross-platform
- 当前状态：PROTOCOL_REVIEW（提案不改变网络协议）
- 当前基线：`24a4ed7bbfab0eb9726ed6261afe5ad56e3f4df7`

## 目标和边界

核对 macOS 与 Windows 当前真实实现，区分必须完全一致的公共行为、语义应一致但实现可不同的能力、合理的平台差异以及需要用户决定的产品范围。

本审计不要求两端复制相同 UI，不修改平台代码、handoff、开发清单、`PROTOCOL.md`、contracts、GitHub Actions、Release、tag 或版本号，也不执行真实 USB、DDC、显示器唤醒或防火墙操作。

## 协议和公共数据状态

- 网络协议：`version = 1`，不变。
- 公共 contracts：`schemaVersion = 1`，不变。
- 已批准 proposal：`specs/proposals/DS-001-protocol-v1-state-machine-conformance.md`。
- 待批准 proposal：`specs/proposals/DS-004-display-controls-and-manual-switch-alignment.md`。
- 公共向量：17 条消息验证向量、16 条状态机向量，两端均已接入。
- DS-004 当前不提出网络字段或已发布数据语义变化。

## 推荐实施顺序

### 第一阶段：恢复事实一致性和配置安全

已完成：

1. macOS Agent 通过 PR #15 更正 M-004 清单状态和 handoff。
2. Windows Agent 通过 PR #14 更正 W-004 handoff 的合并状态和最终 main CI。
3. macOS Agent 通过 PR #15 增加本机 `schemaVersion = 2`、v1/旧键兼容迁移、原数据保留、持久失败安全门和无硬件回归测试。

第三项不改变网络协议或公共数据语义，Windows 已有等价安全行为，因此 Windows 不应被阻塞。

### 第二阶段：共同能力语义

1. 已起草 `DS-004-display-controls-and-manual-switch-alignment.md`，定义显示控制、手动入口、DDC 后端、Windows 本机 schema v3 迁移和共同验收样例；等待用户批准详细行为。
2. 提案获批后，两端分别实施 DDC 接口和手动入口测试；平台私有代码不修改共享文件。
3. 显示控制对齐完成后再单独起草跨平台诊断提案，定义允许公开的逻辑字段、`schemaVersion`、脱敏规则、预览和安全失败行为。

### 第三阶段：产品范围和首次引导

1. 用户已决定 Windows 补齐亮度、对比度、音量和回读控制，并要求两端手动切换入口对齐。
2. 基于已稳定的配置、DDC 能力和诊断字段设计两端首次运行安全引导。
3. 正式签名/安装和协议 v2 分别另立任务，不混入功能对齐实现。

## 兼容、迁移和降级策略

- DS-004 审计本身不改变运行时数据，无迁移。
- macOS 已读取现有 `Displays.Configuration.v1` 数组和旧双显示器键，成功后写入带 `schemaVersion = 2` 的新结构；失败时保留原数据并持久停用自动硬件动作，只有用户成功保存才能解除。
- 未知配置版本必须安全拒绝，不能猜测字段语义或覆盖用户配置。
- 平台专有后端不可用时应报告可用性并安全降级，不得误操作其他显示器。
- Windows 为保存 `WindowsInput` 和 `ReadEnabled` 建议把本机配置升至 `schemaVersion = 3`；v2 缺失字段迁移为 `-1` 和 `true`，既有 Mac 输入源语义不变。
- Windows v3 写入失败时必须保留原 v2 文件并进入安全状态；macOS 本机 schema v2 不变。
